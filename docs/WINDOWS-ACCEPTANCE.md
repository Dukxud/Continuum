# Manual Windows acceptance gate — v1.16

This checklist is for BLACK-PUDDLE, against the exact current PR #16 commit. It is NOT a CI run. No automated CI validation is being requested or claimed.

Record the exact Git commit SHA and mark each item PASS, FAIL, or NOT TESTED. Preserve specific error messages and screenshots for failures. NOT TESTED is not PASS.

## Required behavior

1. Launch using Start-Codex-Scheduler.vbs. The graphical interface opens without leaving a terminal window, and existing preferences remain intact.
2. Switch between full and compact mode. The next-run indicator, quota bars, and pending list display correct information. Historical failures are accessible in Recent results but never occupy the next-run card or upcoming grid. Resize and scroll; progress bars follow their cells and disappear when rows are removed.
3. With WebView2 enabled, verify Appearance explicitly reports WebGL2 ACTIVE (not merely WebView2 available), the dark captured image endcaps are softened, and inspect the approved Aero Liquid material at fixed percentages. Two bars should have staggered optical phases; the shimmer must glide in from outside the left edge, exit cleanly, and never flash at its loop seam. The tighter glint should add shine without washing out the bar color. Its fluid animation continues without changing the authoritative percentage. Switch presets and a custom hex color on live bars; verify the chosen appearance actually changes.
4. Start a separate process with CODEX_BAR_RENDERER=wpf. All bars remain visible using the WPF fallback; live color changes work without losing percentages, flickering into blank controls, or creating duplicate bars.
5. In a controlled developer session, simulate a single WebView2 renderer failure, then check that WPF recovery preserves value, follows resize/scroll, accepts further updates, and cleans up after removal. Do not kill unrelated browser processes.
6. Independently import only the packaged components/AeroProgress module into an unrelated Windows Forms application, without loading Codex code. Set custom consumer metadata in Control.Tag; create and update a progress view; query Get-AeroProgressViewStatus. Verify that the consumer's Tag is unchanged.
7. Schedule one real, non-destructive Codex exec session with the intended local time and account. The session picker must include verified saved 'exec' and 'cli' rollouts, excluding unknown sources. Inspect Windows Task Scheduler: one registered task, correct session identity, pinned worker snapshot, and no visible console. When GUI preferences use an isolated directory, the worker's event log, outcome, launch diagnostics, and retry payload must stay beside its scheduled job file rather than leaking into the normal LOCALAPPDATA directory.
8. Allow a benign scheduled session to complete and inspect Recent results: completed means actual success; failure preserves the Codex exit code. A verified quota postponement is deferred and names the next task, never completed.
9. Cancel a pending task: it disappears from Windows Task Scheduler and the interface, records cancelled, and does not reappear after refreshing.
10. Change accounts or workspaces before a one-time run with Auto-resume OFF, and repeat with Auto-resume ON. Both must refuse execution under another identity. Missing or conflicting workspace identity must fail closed, including at scheduling time.
11. Check the result-history screen and repository suggestions after adding many completed result records; those records must not hide valid scheduled-job evidence.
12. Verify unsigned engineering preview warnings and antivirus treatment without disabling Bitdefender. Confirm that an ordinary push or merge cannot publish a GitHub release.

## Same-conversation execution safety

Before accepting a release, run the isolated worker integration with a real mutex held by another process. The competing worker must return nonzero, must not invoke Codex, and must write a blocked result identifying the duplicate attempt. Verify that releasing the first owner allows a later legitimate job. Simulate native Codex "already has an active writer" and verify it is recorded as blocked rather than silently retrying.

When inspecting preexisting jobs, compare their **pinned runtime** and payload's autoResume field with the candidate. Existing one-time tasks may run old code after a new GUI installation. Never replay a completed or failed Horizon job just to test a scheduler fix, and do not cancel old registrations without reviewing their associated session and work.

## Run-status and appearance-event acceptance

Run a scheduled, non-destructive task while the v1.16 dashboard is open. At startup the run time must default to approximately two minutes ahead (rounded up to a displayed whole minute); the adjacent − and + controls change it one minute without violating the 30-second minimum. When a manually chosen time becomes invalid, pressing + must snap immediately to the first selectable future minute instead of silently doing nothing; − must not schedule an invalid time. An untouched default must refresh while idle; a manually edited or restored future date must remain unchanged. The main Time-to-run cell must place countdown text and its Aero bar side by side rather than stacked. After a normal **Schedule once** success, the Upcoming runs row and status line should update without an unnecessary modal confirmation. Preserve confirmation for dangerous unrestricted access and potentially overlapping work, and retain failure messages. The Latest result should use ASCII separators while UTF-8 Codex replies remain intact. Once Windows reports Running, that same surface and the compact card must switch to a stationary-width working-color Aero Liquid tube with continuously flowing optics, **without any execution percentage, filling animation, or bottom spinner/ticker**. The UI must poll real task state without blocking the Windows Forms message loop. After execution ends, the work animation stops and the most recent persisted outcome plus a concise response preview remain visible in either layout. In **Recent results**, selecting the completed task must show its actual final Codex response and the read-only worker transcript, including the verified `SCHEDULER_QA_COMPLETED` example. Selecting a failed task must show the recorded error; missing or corrupt logs must be labeled, never invented. The **Upcoming runs** list must contain scheduled or actively running jobs only. When all jobs finish, it must disappear completely even if the application has saved results and historical Windows tasks; it must not flicker or show completed/failed jobs. **Recent runs** remains accessible in normal and compact layouts. Recent runs is the single place to inspect a past run's Codex response, read its worker log, or choose **Remove from history**. Verify removal persists after refresh/restart and only changes the display: Windows tasks and .result.json, .jsonl, and worker log files remain untouched. The indeterminate Aero state must be tied to actual Running state only; a latest-result strip may show completion outside the Upcoming runs list, but should not duplicate a running indicator. The only main-queue removal action is the existing Cancel selected action for scheduled jobs. When examining an older pinned worker with no result record, verify the app displays **Ended (no result recorded)** rather than claiming completion. No task execution should be inferred merely from `Due now`.

Exercise the Appearance dialog's independent 5-hour, weekly, countdown, and working color choices (preset and arbitrary RGB), Restore Defaults, Save, and Cancel. Verify four live examples, independent persistence after restart, and transactionally rolled-back changes on Cancel. Verify live previews are not saved by background form-autosave before explicit Save. Run `aero-appearance-dialog.test.ps1` and require a real nonzero process exit for any Forms-event assertion, rather than trusting a PASS after an unhandled dialog exception.

The WPF dashboard visual test must provide pixel evidence of true fill/track contrast and independently moving reflections. The single-pixel red-channel failure recorded on November 2 remains unresolved until a local retest supplies measured colors. Do not weaken the acceptance threshold just to obtain a green suite.
