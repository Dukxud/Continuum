# Manual Windows acceptance gate — v1.16

This checklist is for the exact PR #16 commit on BLACK-PUDDLE. Local execution is not a GitHub Actions run; both use the same acceptance script.

Record the exact Git commit SHA and mark each item PASS, FAIL, or NOT TESTED. Preserve specific error messages and screenshots for failures. NOT TESTED is not PASS.

## Required behavior

1. Launch using Start-Codex-Scheduler.vbs. The graphical interface opens without leaving a terminal window, and existing preferences remain intact.
2. Switch between full and compact mode. The next-run indicator, quota bars, and pending list display correct information. Historical failures are accessible in Recent results but never occupy the next-run card or upcoming grid. Resize and scroll; progress bars follow their cells and disappear when rows are removed.
3. With WebView2 enabled, verify Appearance explicitly reports WebGL2 ACTIVE (not merely WebView2 available), the dark captured image endcaps are softened, and inspect the approved Aero Liquid material at fixed percentages. Two bars should have staggered optical phases; the shimmer must glide in from outside the left edge, exit cleanly, and never flash at its loop seam. The tighter glint should add shine without washing out the bar color. Its fluid animation continues without changing the authoritative percentage. Switch presets and a custom hex color on live bars; verify the chosen appearance actually changes.
4. Start a separate process with CODEX_BAR_RENDERER=wpf. All bars remain visible using the WPF fallback; live color changes work without losing percentages, flickering into blank controls, or creating duplicate bars.
5. In a controlled developer session, simulate a single WebView2 renderer failure, then check that WPF recovery preserves value, follows resize/scroll, accepts further updates, and cleans up after removal. Do not kill unrelated browser processes.
6. Independently import only the packaged components/AeroProgress module into an unrelated Windows Forms application, without loading Codex code. Set custom consumer metadata in Control.Tag; create and update a progress view; query Get-AeroProgressViewStatus. Verify that the consumer's Tag is unchanged.
7. Schedule one real, non-destructive Codex exec session with the intended local time and account. The session picker must include verified saved 'exec' and 'cli' rollouts, excluding unknown sources. Inspect Windows Task Scheduler: one registered task, correct session identity, pinned worker snapshot, and no visible console. When GUI preferences use an isolated directory, the worker's event log, outcome, launch diagnostics, must stay beside its scheduled job file rather than leaking into the normal LOCALAPPDATA directory.
8. Allow a benign scheduled session to complete and inspect Recent results: completed means actual success; failure preserves the Codex exit code. A verified quota denial is blocked and must never create a follow-up task.
9. Cancel a pending task: it disappears from Windows Task Scheduler and the interface, records cancelled, and does not reappear after refreshing.
10. Change accounts or workspaces before a one-time run and verify it refuses execution under another identity. Missing or conflicting workspace identity must fail closed, including at scheduling time. A legacy payload with autoResume=true must not trigger a new retry when run by the candidate worker.
11. Check the result-history screen and repository suggestions after adding many completed result records; those records must not hide valid scheduled-job evidence.
12. Verify unsigned engineering preview warnings and antivirus treatment without disabling Bitdefender. Confirm that an ordinary push or merge cannot publish a GitHub release.

## Same-conversation execution safety

Before accepting a release, run the isolated worker integration with a real mutex held by another process. The competing worker must return nonzero, must not invoke Codex, and must write a blocked result identifying the duplicate attempt. Verify that releasing the first owner allows a later legitimate job. Simulate native Codex "already has an active writer" and verify it is recorded as blocked rather than silently registering a second run.

When inspecting preexisting jobs, compare their **pinned runtime** and legacy payload retry flags with the candidate. Existing one-time tasks may run old code after a new GUI installation. Never replay a completed or failed Horizon job just to test a scheduler fix, and do not cancel old registrations without reviewing their associated session and work.

## Bounded CI validation policy

GitHub Actions is **manual dispatch only** (no push, pull-request, schedule, or self-trigger). The operator explicitly chooses validation attempt **1** or **2** for the candidate; do not dispatch more than two attempts against the same commit. An API-backed guard enforces the two-attempt per-commit ceiling and rejects reruns. Each run has a 35-minute timeout; individual child tests have a 300-second default deadline, with no retry. After two failures, stop and inspect recorded evidence before changing the code. Never modify tests merely to obtain green without preserving behavioral checks. Local validation is one run per exact candidate commit unless new evidence justifies another explicit run.

A failed quota read must disable Schedule even if a cached model catalog is valid; selecting another model or effort cannot re-enable it until a current, model-matched quota snapshot has a verified workspace identity. Compact-mode model changes must use the central refresh coordinator.
